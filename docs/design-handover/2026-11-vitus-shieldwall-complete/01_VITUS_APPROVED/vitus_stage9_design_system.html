04 / Approved information architecture

The features,
in four groups.

Exactly 13 destinations. On desktop, four headings in a single row, one column each. On mobile, four expandable groups.

The homepage is not a 13-page index: it stays organised around Build, Explore, Write, Play, Vitus AI, and Own & Share. World Builder also receives a prominent, distinct introduction.

06 / Engineering contract

Built once.
Used everywhere.

This describes the intended implementation, not changes to the current Shieldwall repository. Framework selection remains open until the existing website stack and hosting are assessed.

Component boundaries

SiteHeaderShared navigation, four-column Features mega-menu, mobile accordion and download CTA.
CreatorSelectorFour roles; persists preference; URL shareability; same page layout.

MediaShowcaseReal app clips or images; manual controls; poster fallback.
StoryStack / RoleCardReuse approved scroll/hover patterns; no touch-only dependencies.

Motion & responsive contract

Motion languageDramatic, but readable. 820 ms for substantial transitions; soft rise for section reveals; shorter 150–220 ms for controls.
CardsLayered stacking, maximum three; restrained depth tilt. No forced scroll locking on mobile.
CarouselsManual + crossfade; no automatic slides/media changes.
DesktopKeep approved Brother Vitus hero, legible feathered shading, and visible software proof.
Tablet / phoneProduct media first. Reduce/remove character art and orange glow before shrinking product screenshots.
Reduced motionRespect OS preference and supply simple fade/no animation alternatives.
KeyboardClickable, escape-dismissable menus; labelled controls; visible focus; no hover-only journeys.

DATA / PERSONALISED FEATURE CONTRACT
Production performance & accessibility requirements
Minimise layout shift with declared image dimensions and poster sizes. Video autoplay is never required for understanding: muted loop only for atmospheric media where appropriate, with a still fallback and pause control. Lazy-load below-the-fold media, but give the primary hero strong loading priority.
Meet WCAG 2.2 AA where applicable. Check 4.5:1 contrast for normal text, 3:1 for large text and UI boundaries where required. Test 320px minimum widths, 200% text zoom, keyboard traversal, touch targets and reduced motion. Target good Core Web Vitals: LCP ≤2.5s, INP ≤200ms and CLS ≤0.1 at the 75th percentile.
Content governance & feature-claim integrity
Feature status and tier come from the latest documented source-of-truth inventory and the authoritative commercial model. Every feature-media pair needs a review date, supported plan, capture source, platform, shipping status and content owner. A future feature may appear in Roadmap but must not look available in the main conversion journey.
Marketing copy is deliberately provisional now. Capture real product media only after the required workflow is user-ready; review app screenshots before publishing. No fabricated endorsements, user counts or product screenshots.
Site and studio separation
brothervitus.com is the proposed canonical international product domain; brothervitus.co.uk redirects. The Shieldwall Games site is a shorter studio identity with project cards and a link to Vitus. Shared logo conventions and colour tokens can be reused, but Vitus's large feature system belongs on the product site.
